# Houdini Collector 0.3.1

> Public beta для SideFX Houdini 21.0.671. Перед рабочим использованием рекомендуется проверить результат на копии сцены.

Инструмент для структурированного сбора и передачи Houdini-проектов — аналог
Collect Files из After Effects и Save Project with Assets из Cinema 4D.
Интерфейс использует штатный PySide2 Houdini 21.0 и имеет fallback для PySide6
в более новых версиях.

Инструмент создаёт отдельный переносимый HIP, оставляет только выбранные OBJ/SOP-ветки и собирает связанные внешние файлы. Исходная сцена сохраняется и после операции автоматически загружается обратно.

Готовый установочный архив находится в разделе **Releases** репозитория.
Для Houdini 21 используйте файл `HoudiniCollector_0.3.1_H21.zip`.

Collect, Project Only, Report Only и Incremental Update.

## Установка

1. Распакуйте архив.
2. Откройте в Houdini Python Shell и выполните `hou.getenv("HOUDINI_USER_PREF_DIR")`, чтобы увидеть пользовательскую папку Houdini 21.0.
3. Скопируйте папки `packages` и `houdini_collector` из архива прямо в эту папку. Должны получиться пути:

   - `$HOUDINI_USER_PREF_DIR/packages/houdini_collector.json`
   - `$HOUDINI_USER_PREF_DIR/houdini_collector/python3.11libs/houdini_collector`

4. Перезапустите Houdini.
5. Добавьте shelf set `Collector` через меню полок и нажмите `Houdini Collector`.

Проверка без перезапуска из Python Shell:

```python
import hou
hou.ui.loadPackage(hou.expandString("$HOUDINI_USER_PREF_DIR/packages/houdini_collector.json"))
from houdini_collector import show
show()
```

## Использование

1. Сохраните исходный HIP.
2. Выделите одну или несколько корневых нод в Network Editor.
3. Откройте `Houdini Collector`.
4. Выберите режим и выполните Scan.
5. Проверьте сгруппированный Asset Inspector. Любую зависимость или группу можно отключить.
6. При необходимости найдите потерянные ссылки через `Find Missing Assets…`.
7. Нажмите `Collect`, `Create Project Copy` или `Save Report`.

Режимы:

- `Selected Branches` — выбранные OBJ/SOP-ветки и связанные зависимости;
- `Whole Scene` — вся сцена, включая `/obj`, `/mat`, `/shop`, `/stage` и `/out`;
- `Selected ROPs` — зависимости выбранных render/ROP-нод;
- `Project Only` — trimmed HIP без копирования и relink внешних файлов;
- `Report Only` — только `manifest/collect.json` и журнал, без Save As или изменения сцены.

Asset Inspector:

- зависимости сгруппированы по имени ассета;
- `Asset` показывает вычисленного владельца или texture set;
- поиск работает по ассету, путям, ноде и параметру;
- фильтры ограничивают таблицу по категории и статусу `Ready/Missing/Output`;
- правая кнопка на группе включает или отключает её целиком.
- границы заголовков можно перетаскивать для изменения ширины столбцов;
- сами заголовки можно менять местами; ширина и порядок сохраняются между открытиями окна;
- двойной клик по `Asset` или `Move to Asset…` переносит выбранные строки в ручную группу;
- `Rename Asset Group…` переименовывает всю группу;
- `Reset Asset to Auto` возвращает автоматическую классификацию и destination.

Состояние Scan сохраняется при повторном Scan и после Relink: флажки,
ручные Asset-группы, раскрытые группы, строка поиска и фильтры восстанавливаются
по стабильному пути параметра. Состояние хранится, пока открыто окно Collector.

Incremental Update:

1. Включите `Incremental Update existing collect`.
2. Через `Browse…` выберите саму существующую collect-папку.
3. Выполните Scan и нажмите `Update Collect`.

Файлы с тем же размером/временем или содержимым переиспользуются. Новые и
изменённые файлы заменяются через временный файл. Collected HIP и manifest
публикуются только после успешного Save/Relink. Старые файлы, которые больше не
используются сценой, автоматически не удаляются.

Presets:

- `Default` и `Client Delivery`;
- `Render Farm` — Selected ROPs и Incremental Update;
- `Archive` — Whole Scene и пользовательские HDA;
- `Lightweight`;
- `Models + Materials`.

`Save Preset…` сохраняет текущий режим и флажки в пользовательских настройках
Houdini Collector. Пользовательский preset можно удалить через `Delete Preset`.

Умный Relink:

1. Нажмите `Find Missing Assets…`.
2. Выберите корневую папку поиска.
3. Проверьте предложенные совпадения и число найденных файлов секвенции.
4. Оставьте флажки только у нужных замен и нажмите `Apply Relink`.

Поиск рекурсивный, не изменяет параметры до подтверждения и сохраняет `$F`,
`$F4`, `####`, `%04d` и UDIM-токены. Анимированные или expression-параметры
автоматически пропускаются с предупреждением.

Навигация в результатах Scan:

- `Node` и `Parameter` отображаются в отдельных столбцах: полный путь ноды и короткое имя параметра;
- двойной клик по `Node` или `Parameter` переходит к ноде, выделяет и центрирует её в Network Editor;
- двойной клик по `Source` показывает первый найденный файл зависимости в Windows Explorer;
- обе команды также доступны через правую кнопку мыши;
- для `$F`-секвенции или UDIM выбирается первый реально найденный файл.

По умолчанию включаются:

- все upstream-входы выбранных нод;
- Object Merge и другие ссылки между нодами, обнаруженные HOM;
- материалы через параметрические ссылки и `shop_materialpath`;
- все OBJ-светильники и камеры — это консервативный режим, чтобы не потерять renderer-specific light linking;
- Redshift proxy `.rs`;
- все найденные кадры `$F`, `$F4`, `####`, `%04d` и UDIM-наборов.

Сбор пользовательских HDA/OTL по умолчанию выключен. Его можно включить перед Scan отдельным флажком.

Цвета таблицы Scan: HDRI — голубой, Megascans — зелёный, material/texture — жёлтый. Статус отсутствующего файла остаётся красным.

Обычная модель и её однозначно связанные текстуры группируются без лишней
вложенности: `geo/models/<model>/textures/<file>`. Владение определяется по
общей OBJ-ветке, расположению исходных файлов и совпадению имени ассета. Если
один материал может относиться к нескольким моделям, он безопасно остаётся в
`tex/mats/<material>`.

## Структура результата

```text
project_collect_v001/
├── project_collect.hip
├── geo/
│   ├── models/<asset>/
│   │   └── textures/
│   └── cache/<node>/
├── tex/
│   ├── mats/<material>/
│   ├── hdri/
│   └── misc/
├── usd/
├── hda/
├── misc/
└── manifest/
    ├── collect.json              # режим, Asset и все зависимости
    ├── collect.log
    └── load_hdas.py
```

Megascans распознаётся консервативно: папка должна находиться в пути Quixel/Megascans либо содержать JSON metadata и минимум две текстуры. В `geo/models/<asset>/` сохраняется структура исходной папки, но копируются только модель и текстуры, которые реально обнаружены в параметрах сохранённых нод и материалов. Неиспользуемые LOD, карты, превью и metadata не копируются.

## Ограничения первой версии

- Поддерживаемая область сцены: OBJ/SOP и `/mat`. Solaris/USD-композиции пока только копируются как файловые ссылки; вложенные USD layers не обходятся рекурсивно.
- Автоматические light-link правила Redshift могут храниться в renderer-specific параметрах. Поэтому режим света сохраняет все OBJ lights/cameras.
- Выражения или анимированные строковые параметры не переписываются автоматически и попадают в `collect.log`.
- Внешние Python/VEX, OCIO/LUT/IES не включены как отдельные специализированные категории в версии 0.3; обнаруженные обычные файловые параметры могут попасть в `misc`.
- HDA/OTL самого Redshift/Maxon намеренно не копируются и не встраиваются: на принимающей машине должен быть установлен совместимый Redshift. Пользовательская HDA-обёртка, которая использует Redshift внутри, продолжает собираться.
- Перед передачей проекта обязательно проверьте `manifest/collect.log` и откройте collected HIP в чистой Houdini-сессии.

## Безопасность

Коллектор никогда не удаляет ноды из исходного файла намеренно. Обычный Collect
использует временную папку, изменяет только копию и загружает исходный HIP обратно.
Существующая папка принимается только при явно включённом Incremental Update.
Этот режим не удаляет orphan-файлы; при сбое уже скопированные новые файлы могут
остаться в collect-папке, но старый HIP и manifest не заменяются до успешного завершения.
